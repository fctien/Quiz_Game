1. 需求與範圍

兩個問題，性質不同：

  • 管理碼忘了怎麼辦？六碼管理碼由 secrets.token_hex(3) 產生， 開班時只顯示一次，之後開考坊存分、查看與匯出累積積分都要它。
  • 成績怕忘記存。Render 免費方案掛不了硬碟，重新部署或休眠重啟後 leaderboard.db 歸零 — 也就是說「存入班級積分」在雲端只是暫存， 真正安全的是把 CSV 匯出到老師自己的裝置，而那一步原本完全靠人記得按。

另外釐清了「固定入口代碼」：它是老師自己取的，不是密碼，忘了看印出來的入口卡即可， 真找不到就重取一組重印，不影響任何資料。只有管理碼需要救援機制。

2. 管理碼：三道保險

2.1 萬用鑰匙 MASTER_CODE（核心）

環境變數，至少六碼（太短視同沒設，免得不小心設成空字串就門戶洞開）。 加在 classroom.check() 裡，所以開考坊、查積分、匯出 CSV 全部自動生效， multiplayer.py 一行都不用改 — 這點在當下很重要（見第 4 節）。

環境設定方式
本機 Windowsset MASTER_CODE=... 後再啟動，或寫進 啟動-Windows.bat
Render服務頁面 → Environment → 新增 MASTER_CODE

2.2 管理碼自動落檔

classroom.create() 產生管理碼的同時，附一行到 quiz_game/班級管理碼.txt （時間、班級代碼、管理碼），已加進 .gitignore。 寫檔失敗（雲端唯讀）一律吞掉 — 備份不能害開班失敗。

2.3 /class 的「忘記管理碼？」

新端點 POST /api/class/recover：輸入萬用鑰匙，列出資料庫裡所有班級與其管理碼。 沒設 MASTER_CODE 時回 404 並說明原因，2.1 與 2.3 自動關閉，行為與原本完全相同。

2.4 順手做的：create() 支援自訂管理碼

create(code, admin=None)，留空才隨機。但還沒接到主持台的欄位上 — 接線需要改 multiplayer.py 第 454 行，當時該檔被另一個 session 佔用（見第 4 節）。

3. 成績備份：新增 static/backup.js

放榜的瞬間自動做三件事，全部在主持台的瀏覽器裡完成，與伺服器無關：

層做什麼擋掉什麼情況
1自動下載 CSV 到主持台這台電腦忘記按「匯出本場成績」
2存進 localStorage，保留最近 20 場，可隨時補匯出自動下載被瀏覽器擋掉；考坊已關；Render 重新部署
3還有場次沒匯出時，關閉考坊與關分頁都先確認當場關掉就再也找不回來

CSV 欄位刻意與伺服器的 /api/mp/export 完全一致 （名次／學號／姓名／組別／分數／答對題數／總題數／課堂加分，含 BOM），兩邊匯出的檔案可以直接互換。

「這一場」用指紋辨識：房號 + 班級 + 主題 + 題數 + 每個人的分數。 重新整理放榜頁不會重複存，「再來一局」分數不同會算成新的一場。

這層備份綁在「這台電腦的這個瀏覽器」。換電腦或清瀏覽器資料就沒了 — 它是保險，不是主檔，正式成績仍以匯出的 CSV 為準。

localStorage 的每一次讀寫都包在 try/catch 裡：無痕視窗、關閉 cookie、空間滿都會丟例外， 一律降級成「顯示警告、請老師手動匯出」，絕不讓備份機制把上課弄壞。

5. 過程中的問題

5.1 備份綁在畫面掛載點上 — 找不到位置就整個不備份

症狀
單元測試「自動下載被觸發」失敗，但「存進去一場」是過的
原因
onFinal() 開頭是 var anchor = querySelector('.joinacts') || getElementById('app'); if (!anchor) return; — 下載寫在這行後面。放榜頁版型一改、class 名一換，備份就靜靜地整個跳過
修法
把「備份」和「畫面」徹底拆開：先 record → 先 download → 產生狀態文字， 最後才找掛載點；找不到就只是沒有那塊 UI，成績照樣已經存好
教訓
保險機制不可以依賴它要顯示的那塊畫面

5.2 測試時碰到了本機的 leaderboard.db

症狀
import app 測端點時噴 sqlite3.OperationalError: disk I/O error
原因
兩件事疊在一起：一是 app.py 在 import 時就會呼叫 leaderboard.init() 與 classroom.init()， 直接開了專案裡的真實 DB；二是這次的掛載檔案系統不支援 SQLite 的鎖
後果
DB 內容沒變（本來就是空的，integrity_check 通過），但留下一個 leaderboard.db-journal。下次啟動程式時 SQLite 會自己回滾並清掉
教訓
測 app.py 一律複製到暫存資料夾再跑，不要在專案資料夾原地 import

5.3 _private() 不認得校園實體 IP

發現
討論課堂區網時查到的，本次未修
內容
multiplayer.py 的 _private() 只認 192.168. / 10. / 172.16~31.。 學校配的是 140.124.x.x 這種 TANet 實體 IP 時， lan_ips() 會把其他網卡全濾掉，主持台那顆 「手機連不到？換一個網址」按鈕就不會出現，現場等於沒有備援網址可切
修法
改成「非 127.x、非 169.254.x 的都算候選」。要動 multiplayer.py，留待下次

7. 順帶釐清的：課堂網路

上課實測過「有的同學連得上、有的連不上」。這個結果本身就排除了 AP 全面隔離（那樣會全部連不上）， 差異出在學生端。依發生率排序：手機偷偷走 4G（iOS 的 Wi-Fi 輔助預設開啟）、 連到不同 SSID（不同 VLAN）、跨 AP 不通、VPN 或私人 DNS。 現場最快的驗證是請連不上的人把行動網路整個關掉再試一次。

關鍵限制：不能一半人連區網、一半人連雲端。 兩台是獨立的伺服器，房號、考坊、積分都不共用 — 只要有一個人連不上，唯一的處理方式就是整班切雲端重開一場。

結論：雲端版當主力、區網當備援。區網在校園 Wi-Fi 上變數太多， 而零星失敗在課堂上最難處理。
